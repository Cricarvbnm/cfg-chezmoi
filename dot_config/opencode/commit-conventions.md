# 提交约定

## 格式

```
<type>(<scope>): <subject>

<body>
```

类型和 scope 必填，subject 一行概括，body 可选但复杂改动建议补充。

## 类型（type）

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat` | 新增内容、新功能 | `feat(日报/2026-05-19)`、`feat(AGENTS)` |
| `change` | 修改已有内容 | `change(templates): 改变标题中的时间格式为ISO` |
| `fix` | 修复错误、bug | `fix(周报/2026-05-22): Windows 路径用反引号包裹` |
| `docs` | 文档变更（README、注释等） | `docs(API): 补充接口参数说明` |
| `ref` | 重构，不改变外部行为 | `ref(login): 提取公共校验逻辑` |
| `test` | 测试相关 | `test(auth): 新增登录模块单元测试` |
| `build` | 构建系统或依赖变更 | `build(deps): 升级 Spring Boot 至 2.5.8` |
| `revert` | 回退某次提交 | `revert: feat(api): 移除新接口` |

### 类型选择规则

| 场景 | 应该用 |
|------|--------|
| 新增日报、周报、知识笔记文件 | `feat` |
| 新写入文档章节、模板段落 | `feat` |
| 修改已有文件的内容 | `change` |
| 修正错误（路径、格式、语法、逻辑） | `fix` |
| 子模块指针更新（仅指针指向变化） | `change(子模块名)` |
| 纯代码格式调整、重命名、提取公共逻辑 | `ref` |
| README、注释、API 文档修改 | `docs` |

**常见误区**：不应将所有内容修改都标记为 `change`。新增内容用 `feat`，修复错误用 `fix`，只有对已有内容的调整、改写、优化才用 `change`。

## scope

scope 表示变更的领域或模块，使用中文或英文均可，但应简洁一致：

- **中文**：`日报/2026-05-19`、`周报/2026-05-22`、`模板`、`知识笔记`
- **英文**：`templates`、`AGENTS`、`build`、`api`、`db`

子模块指针更新时，scope 为子模块名：`change(reports)`、`change(knowledges)`。

## subject 规则

- 使用中文，祈使语气
- 一行概括，不超过 72 字符
- 不加句号结尾
- 第一个字大写

## body 规则（可选）

- 解释**做了什么**和**为什么**，不解释怎么做的细节
- 每行不超过 72 字符
- 多条内容用 `-` 列表

## 其他规则

- 只做本地提交，不执行 `git push`
- 子模块内的变更先在子模块提交，再回主仓库更新指针
- 不提交空变更、不提交未完成的半成品
- 一次提交只包含一个逻辑变更，不把无关内容混在一起
